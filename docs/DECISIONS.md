# Decisions and open questions

## Decisions

| # | Decision | Why |
|---|---|---|
| D1 | Pulse is a search-driven platform. Any product, category or audience | Goal alignment 2026-09-24. Thermal printers were a past project, not the product |
| D2 | Public data only. No company data | Hobby project. Company data can't be used |
| D3 | Web app: Next.js + TypeScript on Vercel, Postgres | One codebase you can maintain alone. You already have Vercel |
| D4 | All AI through Vercel AI Gateway (Claude + Jev) | You already have the key. One bill, spend visible |
| D5 | Jev makes every per-post decision. Claude only plans, proposes the codebook and writes narrative | Jev is validated (≥ 0.8 → 92–100% match) and cheap enough to run on every post. Claude is used where text generation is needed |
| D6 | Numbers from SQL, quotes from the database, Claude cites post IDs | Carries over "every number traces to posts" |
| D7 | Budget ≤ $20/month for all APIs. Prove feasibility on a few hundred posts before scaling | Your constraint |
| D8 | Free sources first (YouTube, Reddit), then ScrapeCreators and Apify | Cost and phasing |
| D9 | Single user, passcode access | Only you use it for now |
| D10 | Headline feature: live customer journey map from real posts | Your "wow factor" |
| D11 | The Python draft from the kickoff is discarded | Replaced by D3 |
| D12 | First search: **HP Smart Tank printers** (a product family) | Your choice, 2026-09-24 |
| D13 | Product catalog (category → family → series → model → SKU, plus services) is a first-class filter | Families span many models and regional SKUs |
| D14 | Regions: North America, China, LATAM, India | Your choice |
| D15 | Claude for planning, codebook, catalog and narrative: Sonnet 5 while testing (`PULSE_CLAUDE_MODEL=anthropic/claude-sonnet-5`), stepping up to Opus 5 only where quality needs it. Jev does the per-post work | Your choice (updated): cheaper models for testing. Per-task model settings come with steps 5 and 8 |
| D16 | Vercel Hobby. Pipeline built as small resumable steps. Upgrade to Pro only if needed | Your choice |
| D17 | Phase 1 scope: Smart Tank, North America only (Amazon.com, YouTube, Reddit) | Your choice. Other regions in Phase 2 |
| D18 | Audience-type searches wait until the product search passes Phase 1 | Your choice |
| D19 | Filters: family → series in Phase 1; model/SKU stored from day one, model filter in Phase 2 | Your choice. Storing early avoids re-scraping |
| D20 | Price: store price observations per listing; price tier *within region*; promo detection via Jev; no exact price per post | Prices vary by region, promotion and date, and reviews rarely state price paid |
| D21 | Per-channel journey and report views, plus a combined journey built stage by stage with channel mix, per-channel sentiment and evidence thresholds. Default is channel-balanced | Channels see different stages and people. Show only what the evidence supports |
| D22 | Reddit is collected through ScrapeCreators, not Reddit's API | Reddit refused API access in the earlier project; ScrapeCreators worked there |
| D23 | Phase 1 feasibility runs on YouTube + Reddit only; Amazon (Apify) follows when credits are topped up | Apify free credits are used up. Trade-off: fewer buy/setup-stage posts, so the journey gate is judged on social data first |
| D24 | Database changes ship as paste-ready SQL for Neon's SQL Editor (`drizzle/editor/`) | The command-line migration needs a local setup; the editor path is what worked |
| D25 | The search box accepts a topic or a question. Questions become a focused, time-bounded collection; the answer card (step 8) gives numbers from SQL and cites posts, and says when evidence is thin | Your request. "How many users" means "how many people posted publicly on the sources read" |
| D26 | Collection is driven by the open search page calling small steps (no background worker yet); closing the page pauses safely | Fits Vercel Hobby without Pro or extra services. Daily refresh of saved searches (cron) comes in Phase 2 |
| D27 | The search page shows a one-line summary with one-click period, depth (Quick 100 / Standard 300 / Deep 1,000 posts per channel, see D28) and source choices; searches are removable chips; everything else sits under "More options". Run saves edits, and exclusions that would drop a search's own results are flagged | Less typing and fewer decisions per search |
| D28 | The post cap is per channel, per run: each channel may add up to the cap in new posts, and a channel that finds fewer keeps fewer (unused room is not passed to other channels) | One shared cap let whichever channel ran first crowd out the others (a Quick run gave 72% YouTube), skewing the source mix by chance. Per channel keeps channels comparable and adding a channel never shrinks the others. A channel finding fewer posts is itself a signal |
| D29 | One product catalog per family (key = normalized subject, e.g. "hp smart tank"), shared by every search of that family and kept when searches are cleared. Claude drafts it once from the model mentions counted in the posts; you review it (rename, merge, add from uncovered mentions, mark verified) and approve. Posts are linked to the most specific series/model they name by whole-word name/alias match (method `alias`); short numbers only count after a family word. Price tiers wait for retailer prices (Phase 2) | Reuse keeps cost at about one AI call per family. Deterministic matching gives exact, explainable counts now; Jev handles ambiguous posts in step 5 |
| D30 | A family can have a **verified reference** committed to the repo (`src/data/catalog-references/`): every series and model with its source URL and an exact quote, checked by tests (maker/major-retailer https pages only; each quote must name the model's number; no duplicate numbers). When one exists it replaces the AI draft, and "Update from verified sources" applies it to an existing catalog, keeping post links. HP Smart Tank's list (27 series, 130 models, checked 2026-09-25) comes from HP's own support product data. HP's robots.txt disallows automated crawling of that data, so it was a one-off lookup of about 150 requests; Pulse never fetches it automatically. Name matching ignores case and spacing, accepts the shared letter once ("smartank"), and accepts tank / ink tank / inktank before a model number, except numbers HP Ink Tank also uses | You asked for no fictitious data: sources are checkable, and anything unproven is listed as left out. Retailer-only status and full regional availability could not be checked (retailers blocked automated access) and are recorded as unknown, not as false |
| D31 | The catalog page is three pickers (Family → Series → Model, defaulting to the most-discussed series) and one card. Models are HP model numbers; SKUs, "e" versions and regional names are other names of the same model. Name variants are matched automatically and shown, not typed; you only add a name Pulse doesn't know (refused if another product already has it, so products are never merged by mistake). Retiring (sunset) hides a series or model from pickers and new reports but keeps past post links. Every action saves immediately. Proposals of new products from posts, and the same pickers on the home page with up to 2 items compared, follow as separate changes. SQL files for the Neon editor are now safe to run twice (from 0003) | You asked for a simple, visual page with defaults and no burden of merging or typing variants; 2 items compared at first, to scale later |
| D32 | The catalog is updated only when you choose: "Update product catalog" proposes (a) series/models in the family's verified reference that the catalog lacks and (b) model numbers written with the family's name in 2+ collected posts, with post count, two short example snippets and a guessed series (nearest model numbers). Proposals are not used anywhere until approved (name and series editable); rejected ones are remembered and never proposed again; approving a proposed series approves its proposed models. You can also add a family (its own catalog), a series or a model by hand from the pickers. Nothing happens automatically after collection. Comparing items moves to a later stage, to be designed so comparisons run consistently | Your call: catalog changes are yours to trigger and approve; comparisons must be reliable before they're offered |
| D33 | The home page starts from the catalog: Family → Series → Model pickers (defaults: first family, all series, all models; retired products hidden) plus an optional question. The planner plans for exactly the pick: subject, kind and names come from the catalog (a series brings its model numbers), every search string must name it, and the pick is stored on the plan (`target`) so reports can filter by it. The search joins that family's catalog at once. "Anything else (type it)" keeps free-text topics outside the catalog. Comparison is deferred (D32) | You asked for the same pickers on the home page with a question section; storing the pick keeps answers scoped to it |
| D34 | The catalog has no Draft/Approve step. A search for a family with a verified list (picked, or typed like "hp smart tank printers") links to that family's catalog automatically, built from the verified list; no AI draft. After each collection Pulse also looks for new products (verified list + models named in 2+ posts). The search page shows one line: the catalog, its model count, and "N new products found → Review" only when something waits. The catalog page has one review card: new products (**Add** / **Skip**, skipped ones aren't suggested again) and, where a verified list exists, products it doesn't contain (**Keep** / **Remove**). "Check for new models" is a quiet link for an on-demand check. Why: every extra choice (Build vs Update vs Approve) made you guess what each did; now the only decisions are about specific products, with their evidence. | 2026-09-25 |
| D35 | The home page is three numbered steps: 1 Product catalog (family tabs, one finder for series and models, scrollable Series and Models lists with a "Posts collected" bar each, most discussed first; review badge and Manage catalog on the tab row), 2 Ask a question (optional; shows exactly what will be searched), 3 Recent searches (Clear list, × per row). The most discussed series with all its models is picked by default, so Plan search always has a target; "Other topic" covers searches outside the catalog. The catalog page uses the same tabs and lists. Posts collected come from your own searches, so the page says they show where you have evidence, not popularity. Picking several products for a comparison comes later with the comparison report (the finder is where those picks will go). | 2026-09-25 |
| D36 | Comparison (a later build, with the comparison report): up to 2 picks at first; a pick is one model or a whole series ("7300 series, all models"); at most one pick per series; "All series" is hidden while comparing. Picks are chosen as chips in the find box. "All series" stays for single-product searches (a family-wide view). | 2026-09-25 |
| D37 | Analysis (step 5): one button, "Analyze N posts · about $X", once collection has finished. Claude drafts the codebook from a sample (no approval step; editable, versioned); Jev answers every question for a post in one call, 2 at a time, as a resumable job like collection. Relevance is strict: a post counts only when Jev is ≥ 0.8 sure it's about the subject or you kept it; less sure ones wait in the optional "Needs a look" list (Keep / Drop) and aren't counted. Other answers use the counted (≥ 0.8) and uncertain (0.5–0.8) bands. Why strict: a yes/no confidence is never below 0.5, so the "< 0.5 review" rule could never trigger, and counting unsure posts would mix off-topic ones into every number. | 2026-09-25 |
| D38 | From the first real run (200 posts: 172 comments, 31 duplicates; 57 of 58 posts naming Smart Tank judged correctly, but 96 posts naming no product were mostly "unsure"): (1) the same text of 40+ characters is one post whoever wrote it (Reddit often gives no author, so author + text missed copies); existing copies are removed when analysis starts. (2) Jev reads each comment with its context: the YouTube video or Reddit thread title (stored at collection; older YouTube comments get it from the free videos.list call) and the catalog products the post names. (3) Relevance is a choice, not yes/no: Smart Tank feedback / other brands / chat (thanks, jokes) / unclear. A post counts when Jev is ≥ 0.8 sure it is product feedback; ≤ 0.2 goes to its group without a look; in between, or "unclear", waits in Needs a look. Posts analysed with the old question are read again ("Re-analyze … with the improved check"). | 2026-09-25 |
