| D29 | One product catalog per family (key = normalized subject, e.g. "hp smart tank"), shared by every search of that family and kept when searches are cleared. Claude drafts it once from the model mentions counted in the posts; you review it (rename, merge, add from uncovered mentions, mark verified) and approve. Posts are linked to the most specific series/model they name by whole-word name/alias match (method `alias`); short numbers only count after a family word. Price tiers wait for retailer prices (Phase 2) | Reuse keeps cost at about one AI call per family. Deterministic matching gives exact, explainable counts now; Jev handles ambiguous posts in step 5 |
| D30 | A family can have a **verified reference** committed to the repo (`src/data/catalog-references/`): every series and model with its source URL and an exact quote, checked by tests (maker/major-retailer https pages only; each quote must name the model's number; no duplicate numbers). When one exists it replaces the AI draft, and "Update from verified sources" applies it to an existing catalog, keeping post links. HP Smart Tank's list (27 series, 130 models, checked 2026-09-25) comes from HP's own support product data. HP's robots.txt disallows automated crawling of that data, so it was a one-off lookup of about 150 requests; Pulse never fetches it automatically. Name matching ignores case and spacing, accepts the shared letter once ("smartank"), and accepts tank / ink tank / inktank before a model number, except numbers HP Ink Tank also uses | You asked for no fictitious data: sources are checkable, and anything unproven is listed as left out. Retailer-only status and full regional availability could not be checked (retailers blocked automated access) and are recorded as unknown, not as false |
| D31 | The catalog page is three pickers (Family → Series → Model, defaulting to the most-discussed series) and one card. Models are HP model numbers; SKUs, "e" versions and regional names are other names of the same model. Name variants are matched automatically and shown, not typed; you only add a name Pulse doesn't know (refused if another product already has it, so products are never merged by mistake). Retiring (sunset) hides a series or model from pickers and new reports but keeps past post links. Every action saves immediately. Proposals of new products from posts, and the same pickers on the home page with up to 2 items compared, follow as separate changes. SQL files for the Neon editor are now safe to run twice (from 0003) | You asked for a simple, visual page with defaults and no burden of merging or typing variants; 2 items compared at first, to scale later |
| D32 | The catalog is updated only when you choose: "Update product catalog" proposes (a) series/models in the family's verified reference that the catalog lacks and (b) model numbers written with the family's name in 2+ collected posts, with post count, two short example snippets and a guessed series (nearest model numbers). Proposals are not used anywhere until approved (name and series editable); rejected ones are remembered and never proposed again; approving a proposed series approves its proposed models. You can also add a family (its own catalog), a series or a model by hand from the pickers. Nothing happens automatically after collection. Comparing items moves to a later stage, to be designed so comparisons run consistently | Your call: catalog changes are yours to trigger and approve; comparisons must be reliable before they're offered |
| D33 | The home page starts from the catalog: Family → Series → Model pickers (defaults: first family, all series, all models; retired products hidden) plus an optional question. The planner plans for exactly the pick: subject, kind and names come from the catalog (a series brings its model numbers), every search string must name it, and the pick is stored on the plan (`target`) so reports can filter by it. The search joins that family's catalog at once. "Anything else (type it)" keeps free-text topics outside the catalog. Comparison is deferred (D32) | You asked for the same pickers on the home page with a question section; storing the pick keeps answers scoped to it |
| D34 | The catalog has no Draft/Approve step. The search page shows one line: the catalog, its model count, and "N new products found → Review" only when something waits. The catalog page has one review card: new products (**Add** / **Skip**, skipped ones aren't suggested again) and, where a verified list exists, products it doesn't contain (**Keep** / **Remove**). "Check for new models" is a quiet link for an on-demand check. Why: every extra choice (Build vs Update vs Approve) made you guess what each did; now the only decisions are about specific products, with their evidence. | 2026-09-25 |

The catalog page uses the same tabs and lists. Posts collected come from your own searches, so the page says they show where you have evidence, not popularity. Picking several products for a comparison comes later with the comparison report (the finder is where those picks will go). | 2026-09-25 |

| D37 | Analysis (step 5): one button, "Analyze N posts · about $X", once collection has finished. Claude drafts the codebook from a sample (no approval step; editable, versioned); Jev answers every question for a post in one call, 2 at a time, as a resumable job like collection. Relevance is strict: a post counts only when Jev is ≥ 0.8 sure it's about the subject or you kept it; less sure ones wait in the optional "Needs a look" list (Keep / Drop) and aren't counted. Other answers use the counted (≥ 0.8) and uncertain (0.5–0.8) bands. Why strict: a yes/no confidence is never below 0.5, so the "< 0.5 review" rule could never trigger, and counting unsure posts would mix off-topic ones into every number. | 2026-09-25 |
| D38 | From the first real run (200 posts: 172 comments, 31 duplicates; 57 of 58 posts naming Smart Tank judged correctly, but 96 posts naming no product were mostly "unsure"): (1) the same text of 40+ characters is one post whoever wrote it (Reddit often gives no author, so author + text missed copies); existing copies are removed when analysis starts. (2) Jev reads each comment with its context: the YouTube video or Reddit thread title (stored at collection; older YouTube comments get it from the free videos.list call) and the catalog products the post names. (3) Relevance is a choice, not yes/no: Smart Tank feedback / other brands / chat (thanks, jokes) / unclear. A post counts when Jev is ≥ 0.8 sure it is product feedback; ≤ 0.2 goes to its group without a look; in between, or "unclear", waits in Needs a look. Posts analysed with the old question are read again ("Re-analyze … with the improved check"). | 2026-09-25 |
| D39 | From the second run (113 about, 30 unsure; many unsure posts were competitor talk or thanks): (1) kinds of post are now about the subject / competitor / chat / off-topic / unclear; competitor posts get which brand (from a competitor list in the codebook, drafted by Claude, editable) and how the writer feels about it, shown as "Competitors mentioned", separate from the subject's numbers. (4) The question set has a version (stored with each answer); posts read with an older set are offered for re-analysis. | 2026-09-25 |
| D40 | Measuring and improving the journey (EVALUATION.md §1): "Check accuracy" shows the same 20 counted posts (stable random order per codebook version) with Jev's sentiment, stage, user type and themes pre-filled; you correct what's wrong. | D41 | Question design for the journey. (1) Relevance is three independent yes/no questions (about the subject? mentions another brand? only chat?), so a comparison counts for the subject and shows under Competitors; and a post that names the product (catalog match in its title or text) counts unless Jev is sure it's chat or off-topic. A post goes to another group without a look only when it's under 35% likely about the subject. (2) New per-post answers: what the post does (question, complaint, praise, advice, comparison, decision), how long they've had it, first-hand or hearsay, severity (score 0–4) and would-recommend (score 0–4). (3) The journey map crosses stage × what people do; each cell is a moment. Severity is shown per theme. (4) Claude auto-check: Claude answers the same questions on the 20 sample posts; you only decide where it disagrees with Jev; your answer always wins. Claude never changes what is counted: numbers stay from Jev's answers (JEV.md). (5) 4 posts read at once, with retries on 429. | 2026-09-25 |
| D42 | No assumptions about how the product works: (1) "How the product works" is a note you write or approve in the codebook (e.g. printheads are installed at setup and can be replaced later); Jev reads it with every post and Claude reads it when drafting and checking.
